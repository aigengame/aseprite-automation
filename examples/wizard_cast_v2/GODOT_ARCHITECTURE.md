# Godot consumer

This project consumes only the v2 `content/wizard_assets/bundle.json` and its PNGs. The bundle is generated by the v2 art workflow. Its schema version, 384 × 288 canvas, component sizes, anchors, phase ranges, frame durations, and cast muzzle are the asset authority. The Godot project does not load v1 files.

| Area | Owner |
| --- | --- |
| Add-ons | None. The small game needs no shared technology layer. |
| Systems | `target_practice.gd` owns the five-cast round, phase transitions, release and outcome counts, completion, and restart rules. It has no asset or scene dependency. |
| Content | `wizard_bundle.gd` checks and imports the delivered bundle. `wizard_range.gd` places its components, coordinates native animation with the round, moves the target and projectile, and resolves collisions. The target center follows the declared muzzle height. The target and projectile collision radii derive from their declared image sizes. |
| UI | `range_hud.gd` presents the round and forwards cast, restart, and quit input. It does not alter round state directly. |
| Bootstrap | `main.gd` creates Content and UI and connects them. |

Dependencies point from the bootstrap to Content and UI, from UI to Content's public actions and signals, and from Content to Systems. Systems do not load Content or UI paths. Content signals state changes and hit feedback to the UI. There are no autoloads.

The 384 × 288 viewport uses nearest-neighbor texture filtering and integer scaling. The default window is 768 × 576. The HUD occupies the top and bottom margins. The target is at x=324 and moves vertically, centered 25 pixels below the muzzle with a 28-pixel amplitude. With the delivered muzzle at (157, 83), the 64 × 84 target and its (32, 39) anchor stay inside y=41–181. The projectile starts at `wizard foot + bundle muzzle`. The game retains the v1 five-cast rules and 32-frame phase timing.

Run `gda scene validate res://main.tscn --project examples/wizard_cast_v2/godot --json`, then `gda script run res://tests/round_rules.gd --project examples/wizard_cast_v2/godot --strict --json`. Before assets exist, `tests/missing_assets.gd` checks the visible error state. Once the v2 bundle is present and imported, run `tests/playable_round.gd` through `gda script run` and inspect its child exit status and diagnostics. The latter test exercises imported PNGs, native animation, real input, hit and miss, result, and restart.
